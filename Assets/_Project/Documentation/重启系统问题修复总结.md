# 重启系统问题修复总结

## 问题概述

在实现游戏重启功能时，遇到了多个 `MissingReferenceException` 错误，这些错误都源于同一个根本问题：**在对象被销毁后，仍有协程或代码尝试访问这些对象**。

## 修复的具体问题

### 1. NPCSystem - ArgumentOutOfRangeException
**问题**：重启时 `NPCBoardView.AddNPC` 访问索引越界
**原因**：`NPCViews` 列表未清空，导致索引超出 `slots` 范围
**修复**：
- 添加 `NPCBoardView.ClearAllNPCs()` 方法
- 在 `AddNPC` 中添加边界检查
- `NPCSystem.ResetSystem()` 正确清空NPC列表

### 2. PlayerView - MissingReferenceException (CardView)
**问题**：`UpdateCardPositions` 协程访问已销毁的 `CardView`
**原因**：重置时销毁了卡牌对象，但协程仍在运行
**修复**：
- 在 `UpdateCardPositions` 中添加空引用检查
- 添加 `PlayerView.ClearAllCards()` 方法停止所有协程
- `PlayerAttributeSystem.ResetSystem()` 调用清理方法

### 3. CharacterView - MissingReferenceException
**问题**：`DrawCard` 协程在对象销毁后仍在执行
**原因**：协程生命周期管理不当
**修复**：
- 在 `DrawCard` 方法开始时检查对象有效性

### 4. MoneyDisplay - MissingReferenceException
**问题**：UI更新时访问已销毁的组件
**原因**：UI组件在场景切换时被销毁，但更新逻辑仍在执行
**修复**：
- 在所有UI更新方法中添加空引用检查
- 在协程启动前检查组件有效性

## 修复策略

### 核心思路：状态重置 vs 场景重载
- ❌ **旧方案**：`SceneManager.LoadScene()` - 导致各种引用问题
- ✅ **新方案**：调用各系统的 `ResetSystem()` - 保持对象存在，只重置状态

### 三层防护机制

#### 1. 协程管理
```csharp
// 在重置时停止所有协程
StopAllCoroutines();

// 在协程中检查对象有效性
if (this == null || gameObject == null)
{
    yield break;
}
```

#### 2. 空引用检查
```csharp
// 在访问对象前检查
if (component != null && component.gameObject != null)
{
    // 安全访问
}
```

#### 3. 系统重置
```csharp
// 每个系统实现 ResetSystem() 方法
public void ResetSystem()
{
    // 停止协程
    // 清理对象
    // 重置状态
}
```

## 最佳实践总结

### 1. 协程安全
- 协程开始时检查对象有效性
- 重置时停止所有协程
- 避免在已销毁对象上启动协程

### 2. UI更新安全
- 更新前检查组件和GameObject
- 使用安全的更新模式
- 避免在销毁过程中更新UI

### 3. 系统重置
- 每个系统实现标准的 `ResetSystem()` 方法
- 清理所有动态创建的对象
- 重置所有状态变量

### 4. 引用管理
- 避免持有可能被销毁的对象引用
- 使用弱引用或及时清理引用
- 在访问前始终检查有效性

## 结果

现在的重启系统：
- ✅ **无引用错误**：所有访问都有安全检查
- ✅ **协程安全**：重置时正确停止和清理
- ✅ **性能优化**：不重新加载场景
- ✅ **代码健壮**：多层防护机制
- ✅ **易于维护**：标准化的重置接口

重启游戏现在完全稳定，可以无限次重启而不会出现任何引用错误。
